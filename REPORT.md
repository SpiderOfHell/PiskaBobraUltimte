## Вариант
№ 42 — «Викторина с таймером».

## Цель работы
Разработать программный продукт «Викторина с таймером» и продемонстрировать использование подходов TDD, ATDD, BDD и SDD.

## Постановка задачи
Приложение должно запускать викторину, ограничивать время ответа на каждый вопрос и подсчитывать баллы. В рамках варианта № 42 необходимо проверить контроль времени и подсчёт баллов (TDD), отказ в зачёте ответа после превышения времени (ATDD), автоматическое закрытие вопроса по истечении времени (BDD), а также проверить примеры времени, ответов и баллов в виде спецификации (SDD).

## Архитектура и реализация
Логика вынесена в `src/quiz_manager.py`. Класс `Question` хранит формулировку, правильный ответ и положительный лимит времени. Класс `QuizManager` хранит список вопросов, текущую позицию и счёт. При первом получении вопроса запускается `threading.Timer`; время измеряется монотонными часами `time.monotonic`, не зависящими от перевода системных часов. По срабатыванию таймера вопрос закрывается независимо от наличия ответа. Поздний ответ отклоняется и не увеличивает счёт. Для следующего вопроса менеджер продвигается после закрытия предыдущего.

`src/quiz_app.py` содержит консольный интерфейс. Он показывает вопросы, принимает ответ с ограничением по времени и выводит текущий и итоговый счёт.

## Этап 1. TDD — разработка через тестирование

Подготовлены модульные проверки:

1. правильный ответ в пределах лимита увеличивает счёт на один;
2. неправильный ответ не увеличивает счёт;
3. срабатывание таймера закрывает вопрос, а поздний правильный ответ не засчитывается;
4. ответ ровно на границе лимита считается опоздавшим;
5. оставшееся время рассчитывается по монотонным часам;
6. некорректный лимит времени отклоняется.

Для детерминированной проверки времени используется внедрение тестовых часов и тестового таймера. Отдельная приёмочная проверка использует настоящий `threading.Timer`.

Команда проверки:

```bash
python -m pytest -v
```

## Этап 2. ATDD — разработка через приёмочные тесты

Проверяются пользовательские сценарии завершённой функциональности:

- пользователь отвечает правильно и получает балл;
- после ответа открывается следующий вопрос;
- после завершения всех вопросов приложение сообщает, что викторина окончена;
- по истечении реального лимита вопрос закрывается, поздний правильный ответ не принимается, счёт не меняется.

Автоматизация находится в `tests/test_atdd.py`.

## Этап 3. BDD — разработка через поведение

В `features/quiz.feature` описаны сценарии на русском языке в формате Gherkin: правильный ответ, неправильный ответ и истечение времени без ответа. Файл `features/steps/quiz_steps.py` связывает шаги сценариев с публичным интерфейсом `QuizManager`. Сценарий истечения времени ожидает срабатывания настоящего таймера и проверяет закрытое состояние вопроса.

Команда запуска:

```bash
python -m behave
```

## Этап 4. SDD — спецификация на примерах

Таблица примеров поведения:

| Лимит, сек. | Время ответа, сек. | Ответ пользователя | Ожидаемый результат | Итоговый счёт |
|---:|---:|---|---|---:|
| 5 | 1 | `4` (верный) | Правильно! | 1 |
| 5 | 1 | `5` (неверный) | Неправильно! | 0 |
| 5 | 5 | `4` (верный, но поздно) | Время истекло! Ответ не засчитан. | 0 |
| 5 | 1 | ` 4 ` (верный с пробелами) | Правильно! | 1 |

Автоматизированная проверка таблицы реализована параметризованным тестом `test_sdd_specification_examples` в `tests/test_tdd_sdd.py`.
